01 / EL MAPA

¿Qué significa Python en full stack?

Full stack significa trabajar con la parte visible de una aplicación, su lógica del servidor y sus datos. Python suele encargarse del backend. El navegador normalmente presenta HTML, aplica CSS y ejecuta JavaScript.

Frontend

Lo que ve y utiliza la persona: botones, formularios y tablas.

En esta demo: HTML + JavaScript.
Backend

Recibe solicitudes, valida datos y ejecuta operaciones.

En esta demo: Python + FastAPI.
Datos

La información que consulta o modifica el backend.

En esta demo: memoria. En una aplicación persistente: una base de datos.
Navegador«Mostrar empleados»
→
API en PythonGET /empleados
→

La respuesta vuelve al navegador como JSON. El frontend transforma esos datos en una tabla. La API es el contrato que permite esa comunicación.

«Python procesa los datos en el servidor; la interfaz los solicita mediante una API y los muestra al usuario».

¿Dónde entra Reflex, el framework de tu documento?

Reflex permite declarar la interfaz y la lógica usando Python. Genera una interfaz React y mantiene comunicación con el backend para gestionar eventos y estado. “Escribir full stack en Python” no significa que el navegador ejecute directamente tus archivos .py. Cómo funciona Reflex.

Tu PDF usa la expresión “Python Flex” para referirse a Reflex. Para exponer, usa el nombre oficial Reflex. El documento menciona Next.js; es un detalle dependiente de la versión. La explicación esencial es componentes Python → frontend React + backend.

Decisión para aprender: aquí usaremos un HTML pequeño como frontend, para ver claramente las peticiones. Las APIs REST y GraphQL también podrían ser consumidas por Reflex. No necesitas instalar Reflex para ejecutar estos ejemplos.

Relación con microservicios

Una API REST no convierte automáticamente una aplicación en microservicios. Un monolito también puede ofrecer REST. Los microservicios separan capacidades de negocio en servicios con autonomía de despliegue y propiedad de sus datos. No hace falta una máquina física distinta por servicio.

En el diseño del PDF, Reflex puede actuar como BFF (Backend for Frontend): adapta datos de servicios para una interfaz. Es una decisión arquitectónica, no una obligación del framework. Esta demo es un servicio educativo de empleados mostrado con dos alternativas de API.

02 / LO MÁS IMPORTANTE

REST: recurso + método + respuesta

REST significa Representational State Transfer. Es un estilo arquitectónico; no es una librería ni un lenguaje. En APIs web suele utilizar HTTP para trabajar con recursos. Nuestro recurso es un empleado.

Una ruta identifica el recurso y el método expresa la operación. Un endpoint se entiende aquí como método + ruta: GET /empleados y POST /empleados hacen cosas distintas aunque compartan la URL.

CRUDMétodoRutaAcciónÉxito
CreatePOST/empleadosCrear201
ReadGET/empleadosListar200
ReadGET/empleados/1Consultar el ID 1200
UpdatePUT/empleados/1Reemplazar los tres campos200
DeleteDELETE/empleados/1Eliminar204

Desarma una petición real

POST http://127.0.0.1:8001/empleados
Content-Type: application/json

{"nombre": "Marta Ruiz", "puesto": "Analista", "salario": 6000}
  • POST: quiero crear un recurso.
  • http: protocolo; 127.0.0.1: mi propia computadora.
  • 8001: puerto donde escucha REST; /empleados: ruta.
  • Content-Type: indica que el cuerpo se envía como JSON.
  • Cuerpo: datos de entrada. El cliente no necesita enviar el ID.

El servidor valida, guarda y responde:

HTTP/1.1 201 Created
Content-Type: application/json

{"nombre": "Marta Ruiz", "puesto": "Analista", "salario": 6000.0, "id": 3}

El orden de las claves JSON no importa. 6000 y 6000.0 expresan aquí el mismo valor numérico.

Cuatro palabras que debes distinguir

HTTP y JSON

HTTP define cómo intercambiar solicitudes y respuestas. JSON es un formato de datos. JSON no es una base de datos. REST puede usar otros formatos.

Ruta y parámetro

En /empleados/{empleado_id}, las llaves marcan un valor variable. Si llega /empleados/1, FastAPI entrega empleado_id = 1 a la función.

Los códigos que mostrarás en clase

CódigoSignificado en esta demo
200Consulta o actualización correcta.
201Se creó un empleado.
204Se eliminó; la respuesta no lleva cuerpo.
404El ID solicitado no existe.
422FastAPI rechazó la entrada: campo faltante, nombre demasiado corto, salario no positivo o ID que no se puede interpretar como entero.
Un poco más: stateless, PUT y PATCH

Stateless significa que la petición debe aportar el contexto necesario para atenderla, sin depender de una conversación previa guardada por el servidor. No significa «prohibido almacenar empleados». Los datos del recurso sí se guardan.

PUT reemplaza los campos editables completos en este ejemplo. PATCH sería una modificación parcial; no está implementado. Repetir el mismo PUT deja el mismo estado: es idempotente. Repetir POST puede crear varios empleados. DELETE es idempotente respecto al estado aunque el segundo intento responda 404.

REST incluye más principios que CRUD: separación cliente-servidor, interfaz uniforme, posibilidad de caché y capas, entre otros. Esta práctica introduce el uso habitual de recursos y HTTP; no desarrolla todas las restricciones de REST.

«Con REST identifico el recurso por su URL y expreso la acción con el método HTTP. El servidor responde con datos y un código de estado».

05 / LEER PYTHON CON SENTIDO

El código REST explicado por bloques

Abre rest_api.py. El orden es: importaciones → aplicación → modelos → datos → endpoints. Los comentarios numerados del archivo coinciden con esta explicación.

Antes: la sintaxis mínima

SintaxisLéelo así
from paquete import herramientaTraer una herramienta de un paquete.
class Nombre:Definir una clase. Aquí describe la forma de un empleado.
nombre: strDeclarar que el nombre es texto. int es entero; float es número con decimales.
def funcion(...):Definir una función. La sangría delimita su bloque.
@app.get(...)Decorador: registra la función que está debajo como manejadora de una ruta GET.
return / raiseDevolver un resultado / lanzar una excepción.
list[Empleado]Una lista cuyos elementos son empleados.

Las anotaciones de tipo de Python por sí solas no validan todo en ejecución. FastAPI y Pydantic las interpretan para procesar los datos de la API.

1–2. Definir entrada y salida

class EmpleadoEntrada(BaseModel):
    nombre: str = Field(min_length=2, max_length=80)
    puesto: str = Field(min_length=2, max_length=80)
    salario: float = Field(gt=0, allow_inf_nan=False)

class Empleado(EmpleadoEntrada):
    id: int

BaseModel aporta validación. Los tres campos son obligatorios. min_length y max_length delimitan la longitud; gt=0 significa “mayor que cero”; allow_inf_nan=False rechaza valores no finitos.

Empleado hereda de EmpleadoEntrada: reutiliza nombre, puesto y salario, y agrega el ID. Así no repetimos los campos. El cliente manda la entrada y el servidor devuelve la salida.

Pydantic puede convertir algunos valores compatibles, por ejemplo una cadena numérica a un número. No estamos activando validación estricta. Las reglas mostradas son básicas; no detectan por sí solas todos los nombres sin sentido o compuestos únicamente por espacios. Restricciones de campos en Pydantic.

«Este modelo es la regla de entrada: necesito nombre, puesto y un salario positivo. El ID lo genera el servidor».

3. Guardar temporalmente los empleados

empleados = {
    1: Empleado(id=1, nombre="Ana Torres", puesto="Desarrolladora", salario=5000),
    2: Empleado(id=2, nombre="Luis Pérez", puesto="Diseñador", salario=4500),
}
siguiente_id = 3

Un diccionario guarda pares clave–valor. empleados[1] accede al objeto de Ana. empleados.values() obtiene los objetos y list(...) los convierte en una lista. El contador empieza en 3 porque ya existen 1 y 2.

Esto no es una base de datos. Al detener o recargar el proceso se pierde la memoria y vuelven los datos iniciales. El contador evita reutilizar el último ID eliminado dentro de esa ejecución.

4–5. GET: consultar una colección o un elemento

@app.get("/empleados/{empleado_id}", response_model=Empleado)
async def obtener_empleado(empleado_id: int):
    if empleado_id not in empleados:
        raise HTTPException(status_code=404, detail="Empleado no encontrado")
    return empleados[empleado_id]
  1. El decorador registra método y ruta.
  2. FastAPI toma empleado_id de la URL e intenta convertirlo a entero.
  3. if ... not in comprueba si no existe la clave.
  4. HTTPException interrumpe el flujo y produce el error HTTP.
  5. Si existe, return devuelve el empleado. FastAPI lo serializa a JSON.

response_model describe, valida y filtra la salida según el modelo indicado. La ruta de lista usa list[Empleado], porque devuelve varios.

6. POST: el bloque principal de tu exposición

@app.post("/empleados", response_model=Empleado, status_code=201)
async def crear_empleado(datos: EmpleadoEntrada):
    global siguiente_id
    nuevo = Empleado(id=siguiente_id, **datos.model_dump())
    empleados[siguiente_id] = nuevo
    siguiente_id += 1
    return nuevo

Recibir y validar

datos: EmpleadoEntrada le indica a FastAPI que lea el JSON del cuerpo y lo valide con Pydantic. Si no cumple, responde 422 antes de ejecutar la función. Cuerpos de petición en FastAPI.

Usar el contador

global siguiente_id permite reasignar la variable del módulo desde la función. Lo necesitamos para += 1. En cambio, modificar una entrada del diccionario no reasigna la variable empleados.

Construir el objeto

model_dump() convierte el modelo validado en un diccionario. ** expande sus campos como argumentos. Equivale a escribir Empleado(id=3, nombre=datos.nombre, puesto=datos.puesto, salario=datos.salario).

Guardar y responder

empleados[siguiente_id] = nuevo guarda el empleado. += 1 prepara el próximo ID. return nuevo devuelve el objeto con estado HTTP 201.

Recorrido que debes memorizar: llega JSON → FastAPI/Pydantic validan → tu función asigna ID y guarda → FastAPI responde JSON con HTTP 201.

7. PUT: reemplazar los campos editables

Recibe dos tipos de datos: empleado_id desde la ruta y datos desde el cuerpo. Primero comprueba que el empleado exista. Construye otro objeto con el mismo ID y sustituye la entrada del diccionario.

Debes enviar nombre, puesto y salario. Si omites uno, recibes 422. Este endpoint no crea empleados cuando el ID no existe: responde 404.

8. DELETE: eliminar sin devolver JSON

del empleados[empleado_id]
return Response(status_code=204)

Después de comprobar la existencia, del elimina esa clave. Response permite devolver explícitamente una respuesta vacía: 204 no debe contener un mensaje JSON. Estados de respuesta en FastAPI.

¿Por qué aparece async def si no hay await?

async def define una función asíncrona que el framework ejecuta. Las operaciones de esta demo son muy cortas y solo usan memoria, así que no hay una espera de red que requiera await. No significa “código automáticamente más rápido”.

Si añadieras una petición HTTP asíncrona, usarías await para ceder el control mientras llega la respuesta. No debes meter llamadas bloqueantes largas en una función asíncrona. El contador y el diccionario de esta demo no sustituyen las garantías de una base de datos.

Archivo REST completo

Al final, app.mount publica únicamente la carpeta web en /web. Path(__file__).parent localiza la carpeta del programa. Esa parte sirve el HTML; no pertenece al CRUD de empleados.

rest_api.py · código real del proyecto
"""Ejemplo REST de empleados. Los datos se guardan solo en memoria."""

from pathlib import Path

from fastapi import FastAPI, HTTPException, Response
from fastapi.staticfiles import StaticFiles
from pydantic import BaseModel, Field

app = FastAPI(title="REST · Empleados", version="1.0")


# 1. Entrada: el cliente envía estos tres campos, sin id.
class EmpleadoEntrada(BaseModel):
    nombre: str = Field(min_length=2, max_length=80)
    puesto: str = Field(min_length=2, max_length=80)
    salario: float = Field(gt=0, allow_inf_nan=False)


# 2. Salida: hereda los campos anteriores y añade el id.
class Empleado(EmpleadoEntrada):
    id: int


# 3. Almacén temporal: diccionario con el id como clave.
empleados = {
    1: Empleado(id=1, nombre="Ana Torres", puesto="Desarrolladora", salario=5000),
    2: Empleado(id=2, nombre="Luis Pérez", puesto="Diseñador", salario=4500),
}
siguiente_id = 3


# 4. READ: consultar todos.
@app.get("/empleados", response_model=list[Empleado])
async def listar_empleados():
    return list(empleados.values())


# 5. READ: consultar uno por el id de la URL.
@app.get("/empleados/{empleado_id}", response_model=Empleado)
async def obtener_empleado(empleado_id: int):
    if empleado_id not in empleados:
        raise HTTPException(status_code=404, detail="Empleado no encontrado")
    return empleados[empleado_id]


# 6. CREATE: recibir JSON, asignar id y guardar.
@app.post("/empleados", response_model=Empleado, status_code=201)
async def crear_empleado(datos: EmpleadoEntrada):
    global siguiente_id
    nuevo = Empleado(id=siguiente_id, **datos.model_dump())
    empleados[siguiente_id] = nuevo
    siguiente_id += 1
    return nuevo


# 7. UPDATE: reemplazar los tres campos; conservar el id.
@app.put("/empleados/{empleado_id}", response_model=Empleado)
async def actualizar_empleado(empleado_id: int, datos: EmpleadoEntrada):
    if empleado_id not in empleados:
        raise HTTPException(status_code=404, detail="Empleado no encontrado")
    actualizado = Empleado(id=empleado_id, **datos.model_dump())
    empleados[empleado_id] = actualizado
    return actualizado


# 8. DELETE: eliminar y responder sin cuerpo.
@app.delete("/empleados/{empleado_id}", status_code=204)
async def eliminar_empleado(empleado_id: int):
    if empleado_id not in empleados:
        raise HTTPException(status_code=404, detail="Empleado no encontrado")
    del empleados[empleado_id]
    return Response(status_code=204)


# Opcional: publica la guía y el frontend de práctica en /web/.
# Path pertenece a Python; StaticFiles viene de Starlette a través de FastAPI.
app.mount(
    "/web",
    StaticFiles(directory=Path(__file__).parent / "web", html=True),
    name="web",
)
06 / ENSAYA CON PETICIONES REALES

Tu demostración REST, en orden

Empieza con REST recién iniciado. Si ya creaste empleados desde la demo o Swagger, usa el ID que devuelva tu POST; puede ser distinto de 3.

Opción visual: Swagger

  1. Abre http://127.0.0.1:8001/docs.
  2. Expande GET /empleados → Try it out → Execute.
  3. Muestra el JSON y el Code 200 en “Server response”.
  4. Abre POST /empleados, pulsa Try it out, pega el cuerpo del ejemplo y ejecuta.
  5. Muestra 201 y el ID generado; luego repite GET.
  6. Para PUT o DELETE, introduce el ID devuelto por POST en el campo empleado_id.

“Example Value” muestra un ejemplo de documentación; “Server response” es la respuesta real. Swagger es un cliente que hace peticiones a la API, igual que el frontend o curl.

1. Listar y consultar

curl -i http://127.0.0.1:8001/empleados
curl -i http://127.0.0.1:8001/empleados/1

Resultado: 200; primero una lista con Ana y Luis y después un objeto con Ana. curl es un cliente HTTP de terminal. -i muestra también las cabeceras y el código.

2. Crear

curl -i -X POST http://127.0.0.1:8001/empleados \
  -H 'Content-Type: application/json' \
  -d '{"nombre":"Marta Ruiz","puesto":"Analista","salario":6000}'

Resultado: 201 y Marta con un ID nuevo. -X elige el método, -H añade una cabecera y -d envía el cuerpo. La barra \ permite continuar el comando en la siguiente línea: no añadas espacios después de ella.

{"nombre":"Marta Ruiz","puesto":"Analista","salario":6000.0,"id":3}

3. Actualizar

curl -i -X PUT http://127.0.0.1:8001/empleados/3 \
  -H 'Content-Type: application/json' \
  -d '{"nombre":"Marta Ruiz","puesto":"Líder de QA","salario":6500}'

Resultado: 200; mismo ID, nuevo puesto y salario. El cuerpo sigue incluyendo los tres campos requeridos.

4. Eliminar y comprobar

curl -i -X DELETE http://127.0.0.1:8001/empleados/3
curl -i http://127.0.0.1:8001/empleados/3

Resultado: primero 204 sin cuerpo. Después 404 con:

{"detail":"Empleado no encontrado"}

5. Provocar un error de validación

curl -i -X POST http://127.0.0.1:8001/empleados \
  -H 'Content-Type: application/json' \
  -d '{"nombre":"Marta Ruiz","puesto":"Analista","salario":-10}'

Resultado: 422. En detail verás la ubicación ["body", "salario"] y la regla de “mayor que cero”. No se guarda un nuevo empleado.

«El 404 lo decido en mi función cuando no encuentro el recurso. El 422 lo genera FastAPI al validar la entrada antes de llamar a mi función».
07 / CERRAR EL CIRCUITO FULL STACK

Del botón al backend Python

Con REST encendido, abre Abrir el frontend de práctica. Pulsa «Cargar empleados», crea uno y vuelve a cargar. Debajo verás la petición y la respuesta reales.

La llamada esencial en el navegador es:

const respuesta = await fetch('/empleados');
const empleados = await respuesta.json();

fetch realiza por defecto un GET. await espera su resultado sin bloquear la interfaz. respuesta.json() interpreta el cuerpo JSON como datos de JavaScript. Luego el código recorre la lista y crea filas de tabla.

Para crear, el frontend envía los datos de los campos del formulario:

const respuesta = await fetch('/empleados', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    nombre: 'Marta Ruiz',
    puesto: 'Analista',
    salario: 6000
  })
});

JSON.stringify transforma el objeto en texto JSON. El archivo web/demo.html incluye además manejo de errores y comprueba respuesta.ok: fetch no lanza automáticamente una excepción por un 404 o un 422.

Una sola dirección base: la página y REST se sirven desde http://127.0.0.1:8001. Por eso la ruta relativa funciona y no necesitas configurar CORS. Abrir el archivo de la demo con doble clic no equivale a servirlo desde la API.

Puedes abrir las herramientas del navegador → Network / Red y pulsar el botón: verás la petición /empleados, su método, su estado y el JSON. La validación del formulario ayuda al usuario, pero el backend también valida porque se puede llamar directamente con curl.

08 / LA OTRA FORMA DE PEDIR DATOS

GraphQL: pide los campos que necesitas

GraphQL es un lenguaje de consulta para APIs y un sistema de ejecución. El servidor define un esquema; el cliente selecciona campos permitidos por ese esquema. No es una base de datos ni permite consultar automáticamente cualquier dato del servidor.

Esta implementación usa una ruta, /graphql, y dos clases de operación: query para leer y mutation para cambiar datos. Aquí implementamos lectura y creación para mantener pequeño el ejemplo. Consultas y selección de campos en GraphQL.

Primera query · solo nombres

En GraphiQL, pega una operación y pulsa el botón ▶. También puedes copiar desde consultas.graphql.

query {
  empleados {
    nombre
  }
}

Con el servidor recién iniciado:

{
  "data": {

Añade puesto debajo de nombre y ejecuta otra vez. Ahora llegan esos dos campos. Esta es la comparación más clara con el GET de nuestra API REST, que devuelve el objeto completo que definió el servidor.

Consultar un empleado

query {
  empleado(id: 1) {
    nombre
    puesto
  }
}

id: 1 es un argumento GraphQL. Si usas 999, este resolver devuelve null: el esquema permite que no exista un resultado.

Crear con una mutation

mutation {
  crearEmpleado(datos: {
    nombre: "Marta Ruiz"
    puesto: "Analista"
    salario: 6000
  }) {
    id
    nombre
  }
}

La primera parte envía los datos; las llaves finales piden qué campos devolver después de crear. El resultado contiene data.crearEmpleado. El ID será 3 si es la primera creación de esa ejecución.

Strawberry convierte por defecto crear_empleado en crearEmpleado. El nombre Python usa guiones bajos; en GraphiQL usamos camelCase. Mutations de Strawberry.

Las reglas de longitud y salario se comprueban con if dentro de la mutation. Declarar salario: float establece su tipo, pero no impone que sea positivo. Si envías salario negativo, la respuesta contiene errors.

GraphQL también utiliza HTTP en esta demo. Un fallo al ejecutar un resolver puede venir en errors aunque el estado HTTP sea 200. No significa que GraphQL siempre devuelva 200: errores de transporte o una petición HTTP inválida pueden usar otros códigos. Examina el cuerpo y el estado.

El cuerpo HTTP es JSON. Dentro del campo query viaja un texto escrito en lenguaje GraphQL. El README.md incluye también el comando curl para crear.

Archivo GraphQL completo

El ejemplo usa una lista: append añade el nuevo objeto y for recorre empleados para buscar uno. No hay consultas a disco ni a servicios externos. Los resolvers son cortos; si añades trabajo bloqueante, tendrás que adaptar su ejecución. Integración de Strawberry con FastAPI.

"""Ejemplo GraphQL. Su memoria es independiente de la del ejemplo REST."""

import strawberry
from fastapi import FastAPI
from strawberry.fastapi import GraphQLRouter


# 1. Tipo de salida que el cliente puede consultar.
@strawberry.type
class Empleado:
    id: int
    nombre: str
    puesto: str
    salario: float


# 2. Tipo de entrada para crear un empleado.
@strawberry.input
class EmpleadoEntrada:
    nombre: str
    puesto: str
    salario: float


empleados = [
    Empleado(id=1, nombre="Ana Torres", puesto="Desarrolladora", salario=5000),
    Empleado(id=2, nombre="Luis Pérez", puesto="Diseñador", salario=4500),
]
siguiente_id = 3


# 3. Query: operaciones de lectura.
@strawberry.type
class Query:
    @strawberry.field
    def empleados(self) -> list[Empleado]:
        return empleados

    @strawberry.field
    def empleado(self, id: int) -> Empleado | None:
        for empleado in empleados:
            if empleado.id == id:
                return empleado
        return None


# 4. Mutation: una operación que modifica datos.
@strawberry.type
class Mutation:
    @strawberry.mutation
    def crear_empleado(self, datos: EmpleadoEntrada) -> Empleado:
        global siguiente_id
        if not 2 <= len(datos.nombre.strip()) <= 80:
            raise ValueError("El nombre debe tener entre 2 y 80 caracteres")
        if not 2 <= len(datos.puesto.strip()) <= 80:
            raise ValueError("El puesto debe tener entre 2 y 80 caracteres")
        if datos.salario <= 0:
            raise ValueError("El salario debe ser mayor que cero")
        nuevo = Empleado(
            id=siguiente_id,
            nombre=datos.nombre,
            puesto=datos.puesto,
            salario=datos.salario,
        )
        empleados.append(nuevo)
        siguiente_id += 1
        return nuevo


# 5. Unimos el contrato y lo publicamos en una ruta HTTP.
schema = strawberry.Schema(query=Query, mutation=Mutation)
app = FastAPI(title="GraphQL · Empleados")
app.include_router(GraphQLRouter(schema), prefix="/graphql")

Atención: REST y GraphQL tienen almacenes separados. Crear Marta en REST no hace que aparezca en GraphQL. Son dos ejemplos independientes del mismo concepto.

11 / COMPRUEBA QUE LO ENTENDISTE

Preguntas que podrían hacerte

¿FastAPI y Uvicorn son lo mismo?

No. FastAPI define la aplicación y las rutas. Uvicorn es el servidor que escucha HTTP y ejecuta esa aplicación mediante ASGI. ASGI es una interfaz entre el servidor y la aplicación Python.

¿Por qué no mandamos el ID al crear?

Porque el servidor se encarga de asignarlo. Así el cliente manda los datos editables y la respuesta incluye el identificador generado.

¿Qué ocurre si envío /empleados/hola?

FastAPI no puede convertir “hola” al entero declarado en la ruta. Responde 422 antes de ejecutar la función. Si envías un entero válido que no existe, la función responde 404.

¿Los cambios quedan guardados al cerrar?

No. El diccionario y la lista viven en RAM. Al reiniciar se ejecuta el archivo de nuevo y se restauran los dos empleados iniciales.

¿GraphQL consulta directamente una base de datos?

No necesariamente. Ejecuta resolvers definidos por el servidor. Aquí los resolvers leen una lista; podrían consultar una base de datos u otra API.

¿Por qué GET /empleados no devuelve una página bonita?

Porque es un endpoint de datos que responde JSON. El frontend toma esos datos y los presenta. La página de práctica se sirve por separado en /web/demo.html.

¿Reflex es obligatorio para usar Python full stack?

No. Puedes usar Python en el backend con HTML y JavaScript en el frontend. Reflex es una alternativa que permite declarar también la interfaz en Python.
